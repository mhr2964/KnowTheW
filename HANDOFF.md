## Traps

- **BDL's `/player_season_stats` returns a player's CURRENT team for every historical season queried, not their team at the time of that season** — confirmed live 2026-09-05: Jewell Loyd's real 2018 season row reports "Las Vegas Aces" (her 2025+ team) instead of "Seattle Storm" (her actual 2018 team). Confirmed the per-game `/player_stats` endpoint does NOT have this bug (it correctly returned SEA for the same 2018 game, since it's tied to a specific past game record rather than a mutable current-roster pointer). **This affects any already-shipped feature that surfaces a `teamAbbr` sourced from `getLeagueStatLines` for a past season** — concretely, League Leaders' (Feature 2) team column can show a wrong team for a traded player when viewing a season before their most recent trade. All-Time Leaders (Feature 9) is not visibly affected in practice (its team display already intentionally shows "most recent team," which happens to coincide with what the buggy field returns anyway) but that's accidental, not a correct design. This bug is why Franchise Leaders (roadmap item 10) was built and then withdrawn before commit rather than shipped — a team filter on this field would silently misattribute a traded player's whole career to their current team (confirmed: the withdrawn code showed Jewell Loyd with "11 seasons" on the Aces). A real fix needs team-per-season derived from per-game data instead, the same pattern `seasonStats.js`'s `aggregateToSeasonRow` already uses for the single-player path (not affected by this bug for exactly that reason) — likely a per-league-season bulk scan with Notable Games' cost profile, or a cheaper derivation not yet found. See `docs/design/reference-site-features-roadmap.md`'s item 10 for the full writeup.
- **A cold per-season/per-league bulk `/player_stats` (per-game) fetch can take 2+ minutes**, not from a bug but from real BDL-side per-request latency variance — confirmed live via a page-by-page diagnostic: most pages ~150-300ms, one spiked to 57 seconds. `/player_season_stats` (season-aggregate, used by League Leaders/Career Leaders) does NOT have this problem — it's fast (~1s for a full 24-season loop). Only the per-GAME bulk endpoint (Notable Games' data source) is exposed to this. Each affected season's result is cached forever in-process once fetched, so this is a one-time-per-season-per-server-process cost, not per-visitor — but a fresh dyno/restart pays it again. Worth adding to a warming routine eventually (`scripts/seed-distributions.js`'s Mongo-based pre-warm approach wouldn't help here — this cache is in-process only).
- **BDL's own player bio fields (height/weight/college) are unreliable** — confirmed live (Feature 4): a real row returned `weight: "Maryland"`, clearly a college value in the wrong field. This site already sources bio data from ESPN instead of BDL, which is why this was never a live bug for end users — noted here so a future session doesn't try to "improve" bio data by reading it from BDL.
- **BDL id-resolution failures silently drop PBP/Advanced data** for that player's BDL-era seasons — no ESPN fallback, unlike other methods. See `docs/design/provider-architecture.md` and commit `7224c98`.
- **`writeCache()`'s 400MB storage guard is load-bearing for every cache collection app-wide** (`9b4efa4`) — a real incident (Mongo free-tier quota filled mid-backfill) drove this. Do not remove or raise casually.
- **Percentile coverage is perGame/totals/per36/adjShooting only** (`percentileClient.js`'s `PERCENTILE_STATS`) — Per 100 Poss has no league-wide team-pace fetch yet, so its toggle stays intentionally hidden rather than shown-and-broken.
- **Adding a new player stat-type tab touches THREE places, not two**: `DetailedStats.jsx`'s `ALL_TABLE_TYPES`/`SOURCE_ACTIVE`/render branch (obvious), AND `PlayerRoutePage.jsx`'s own `VALID_TABS` allowlist for URL-tab sync (easy to miss).
- **Heroku Scheduler add-on is installed but has no scheduled-job entries** — both `/internal/jobs/notifications/poll` (pre-game) and `/internal/jobs/notifications/injuries/poll` are built/tested/routed but dormant. Needs a one-time manual step from the user: `heroku addons:open scheduler`, add two jobs (`curl -s -X POST -H "x-scheduler-token: $SCHEDULER_TOKEN" https://knowthew.net/internal/jobs/notifications/poll` every 10 min, and the same with `/injuries/poll` hourly).
